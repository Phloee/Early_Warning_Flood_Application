BAGIAN 1: PENDAHULUAN

1.1 Tujuan Dokumen
Dokumen ini menjelaskan implementasi final proyek Early Warning Flood Application berdasarkan source code aktual pada repository GitHub: https://github.com/Phloee/Early_Warning_Flood_Application.git. Dokumen ini memuat detail source code, struktur direktori, modul backend, modul frontend, dashboard admin, integrasi CCTV, integrasi video simulasi, integrasi dataset Roboflow YOLOv8, alur analisis AI, serta panduan menjalankan aplikasi secara lokal.

1.2 Ruang Lingkup
Ruang lingkup implementasi meliputi:
- Backend Django untuk REST API, dashboard, autentikasi, manajemen wilayah, CCTV, cuaca, notifikasi, dan log analisis banjir.
- Frontend Flutter untuk aplikasi mobile Jakairta.
- Dashboard web untuk operator/admin yang menampilkan area, CCTV live, simulasi video, status banjir, status genangan, rekomendasi, notifikasi, dan CRUD data.
- Computer Vision YOLOv8 untuk mendeteksi kondisi aman, siaga, dan banjir dari frame CCTV atau video simulasi.
- Dataset Roboflow berformat YOLOv8 dengan label aman, banjir, dan siaga.
- Model hasil training YOLOv8 best.pt yang digunakan oleh backend untuk inferensi.
- Database SQLite pada development lokal dan dukungan DATABASE_URL untuk PostgreSQL pada production.
- API documentation menggunakan drf-spectacular Swagger/OpenAPI.

BAGIAN 6: COMPUTER VISION, DATASET, DAN YOLOv8

6.1 Dataset Roboflow
Dataset yang digunakan berasal dari export Roboflow YOLOv8:
- Folder: datasets/banijirbjir_v1/
- File konfigurasi: datasets/banijirbjir_v1/data.yaml
- Format: YOLOv8 detection dataset
- Source metadata: workspace owenval-s-workspace, project banijirbjir, version 1
- URL dataset: https://universe.roboflow.com/owenval-s-workspace/banijirbjir/dataset/1
- License: CC BY 4.0

Isi data.yaml:
train: train/images
val: valid/images
test: test/images
nc: 3
names: ['aman', 'banjir', 'siaga']

Label:
- aman: kondisi tidak banjir/tidak ada genangan signifikan.
- siaga: mulai terlihat genangan atau air awal.
- banjir: area air dominan/banjir jelas.

6.2 Training Model
Training dilakukan menggunakan Ultralytics YOLOv8 dari base model yolov8n.pt. Model lama tidak digunakan sebagai starting point karena model lama hanya mengenal satu class banjir, sedangkan dataset baru memiliki tiga class: aman, banjir, siaga.

Output training:
- yolov8_flood_vision/runs/banijirbjir_v1/weights/best.pt
- yolov8_flood_vision/runs/banijirbjir_v1/weights/last.pt

Deployment model:
- jakairta_backend/models/flood/best.pt sebagai model aktif backend.
- yolov8_flood_vision/best.pt sebagai copy model vision/training folder.

6.3 Integrasi Model ke Backend
File utama:
- jakairta_backend/apps/cctv/vision.py

Fungsi penting:
- get_flood_model_path(settings): mencari model best.pt dari beberapa path kandidat.
- load_flood_model(model_path): load YOLO model dengan cache.
- capture_frame(source): mengambil frame dari stream/video.
- analyze_frame(frame, settings, conf=0.25, area=None): inferensi YOLO pada satu frame.
- aggregate_frame_results(frame_results): menggabungkan hasil beberapa frame.
- analyze_video_source(source, settings, area=None, conf=0.25): analisis multi-frame dari video/stream.

6.4 Logika Analisis
Alur analisis CCTV:
1. Dashboard memanggil /dashboard/analyze/<camera_id>/.
2. Backend membaca stream CCTV.
3. Sistem mengambil beberapa frame dari stream.
4. YOLOv8 mendeteksi label aman, siaga, banjir.
5. Backend menghitung water_area_ratio, confidence_score, risk_level.
6. Hasil disimpan ke FloodAnalysisLog.
7. Area status diperbarui hanya dari CCTV real.
8. Dashboard menampilkan hasil terbaru.

Alur analisis simulasi:
1. Dashboard memanggil /dashboard/analyze_sim/<sim_id>/.
2. Backend membaca video simulasi.
3. Sistem menganalisis berdasarkan fase: start, middle, end, atau auto.
4. Fase start diperlakukan sebagai baseline aman.
5. Fase middle menunjukkan siaga/mulai banjir jika air mulai tampak.
6. Fase end menunjukkan banjir jika air dominan.
7. Hasil simulasi disimpan sebagai log simulation.
8. Hasil simulasi tidak mengubah status live area/CCTV agar tidak mencampur data uji dengan kondisi real.

6.5 Aturan Status
Status	Kondisi	Risk Level	Rekomendasi
AMAN	Tidak ada air atau deteksi lemah/noisy	Safe	Kondisi aman, tetap monitoring
SIAGA	Ada genangan awal atau air mulai muncul	Warning	Pantau kondisi, ada potensi genangan
BANJIR	Air dominan/luas dan confidence kuat	Critical	Evakuasi/ambil tindakan darurat

6.6 Penanganan False Positive
Beberapa CCTV dapat menghasilkan refleksi jalan, bayangan pohon, kendaraan, atau permukaan beton yang terlihat seperti air. Oleh karena itu sistem menerapkan guard:
- Confidence rendah tidak langsung menjadi BANJIR.
- Label siaga tidak otomatis naik ke critical.
- Jika status final AMAN, water_area_ratio dikembalikan ke 0.0 agar UI tidak menampilkan AMAN tetapi area tergenang tinggi.
- Simulasi tidak boleh meng-overwrite status CCTV real.
- CCTV real dan video simulasi dipisahkan secara log dan status.

7.3 Run Backend Lokal
Langkah:
1. Clone repository:
   git clone https://github.com/Phloee/Early_Warning_Flood_Application.git
2. Masuk ke folder project:
   cd Early_Warning_Flood_Application/jakairta_backend
3. Buat virtual environment:
   python -m venv venv
4. Aktifkan virtual environment:
   source venv/bin/activate
5. Install dependency:
   pip install -r requirements.txt
6. Copy environment:
   cp .env.example .env
7. Isi SECRET_KEY dan konfigurasi lain pada .env.
8. Jalankan migrasi:
   python manage.py migrate
9. Buat superuser:
   python manage.py createsuperuser
10. Jalankan server development:
   python manage.py runserver 127.0.0.1:8080
11. Buka dashboard:
   http://127.0.0.1:8080/dashboard/
12. Buka API docs:
   http://127.0.0.1:8080/api/docs/

7.4 Run Frontend Flutter Lokal
Langkah:
1. Masuk ke folder Flutter:
   cd Early_Warning_Flood_Application/jakairta
2. Install dependency:
   flutter pub get
3. Jalankan aplikasi:
   flutter run
4. Build APK:
   flutter build apk --release

BAGIAN 8: DETAIL PERUBAHAN DARI DOC-3

8.1 Perubahan Sumber Data
Desain awal menggunakan sensor IoT fisik. Implementasi final mengganti pendekatan tersebut dengan kombinasi:
- API BMKG untuk data cuaca resmi.
- Weather API/OpenWeather untuk data cuaca tambahan.
- CCTV stream dan video simulasi sebagai sumber visual genangan.

8.2 Perubahan Arsitektur AI
Desain awal hanya memprediksi berdasarkan data ketinggian air/cuaca. Implementasi final menambahkan pipeline Computer Vision:
- Dataset Roboflow berlabel.
- Training YOLOv8.
- Inference real-time/multi-frame.
- Status aman, siaga, banjir.
- Evidence per-frame.
- Logging hasil analisis.

8.3 Perubahan Dashboard
Dashboard final bukan hanya monitoring statis, tetapi memiliki:
- Live CCTV panel.
- Simulation video panel.
- CRUD kamera dan simulasi.
- Status genangan dan area tergenang.
- Overlay bounding box.
- Rekomendasi aksi.
- Notifikasi banjir.
- Separation antara data live dan data simulasi.

Dataset Roboflow banijirbjir_v1 sudah digunakan sebagai dataset training YOLOv8 dengan 3 class: aman, banjir, siaga. Model hasil training disimpan sebagai best.pt dan dipakai backend melalui get_flood_model_path().

D. Catatan Keterbatasan
- Akurasi YOLO sangat bergantung pada jumlah dan variasi dataset.
- Dataset kecil dapat menyebabkan false positive pada refleksi jalan, bayangan, beton basah, dan objek kendaraan.
- Untuk peningkatan akurasi production, perlu penambahan data label dari CCTV nyata, kondisi hujan, kondisi siang/malam, sudut kamera berbeda, kondisi aman, siaga awal, dan banjir total.

E. Rekomendasi Pengembangan Lanjutan
- Tambah dataset minimal 300-500 gambar per class.
- Label ulang frame simulasi yang salah/ambigu di Roboflow.
- Tambahkan confidence calibration per class.
- Tambahkan segmentation model jika ingin estimasi area genangan lebih akurat.
- Deploy backend ke cloud dengan PostgreSQL dan storage media terpisah.
- Tambahkan CI/CD GitHub Actions untuk test dan deployment.
